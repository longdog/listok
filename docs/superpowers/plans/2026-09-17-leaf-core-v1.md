# leaf-core v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Реализовать детерминированную Linux x86_64 библиотеку C++20 для анализа одного изолированного листа: публичный C++ API, стабильный C ABI v1, CLI, M1–M5, асимметрия, score, quality, debug и полный verification harness.

**Architecture:** Контракты и версии фиксируются до алгоритмов; чистые geometry/statistics не зависят от OpenCV, а CV-стадии передают друг другу только узкие domain contracts. `Analyzer` синхронно оркестрирует стадии, останавливается на первой предметной ошибке и перехватывает исключения; JSON, CLI, debug и C ABI остаются адаптерами.

**Tech Stack:** C++20; C11 для ABI consumer; CMake 3.24+; GCC 11.2+ или Clang 14+; system OpenCV 4.5.5+ major 4 (`core`, `imgproc`, `imgcodecs` только для CLI); nlohmann/json 3.11.2+ major 3; GoogleTest 1.14.0+ только для tests.

## Global Constraints

- Scope: Linux x86_64. Не реализовывать ML/ONNX, Android, iOS, Flutter, mobile builds, Windows, GUI, сеть, GPS, карты, сервер или облачное хранение.
- C++20; CMake минимум 3.24; GCC минимум 11.2 или Clang минимум 14.
- OpenCV минимум 4.5.5 и major 4, всегда system dependency через `find_package`; `imgcodecs` разрешён только CLI.
- nlohmann/json минимум 3.11.2 major 3 и GoogleTest минимум 1.14.0 сначала ищутся как installed packages. Только `LEAF_FETCH_DEPS=ON` разрешает `FetchContent` этих двух зависимостей по release archive с SHA-256. Default `OFF`; configure не обращается к сети.
- Обязательные options: `LEAF_BUILD_TESTS`, `LEAF_BUILD_CLI`, `LEAF_BUILD_BENCHMARKS`, `LEAF_ENABLE_DEBUG`, `LEAF_FETCH_DEPS`, `LEAF_ENABLE_SANITIZERS`.
- Обязательные targets при соответствующих options: `leaf-core`, `leaf-core-c`, `leaf-analyzer`, `leaf-core-tests`.
- Stable headers находятся только в `include/leaf/`, не включают OpenCV, не упоминают `cv::*`, не передают владение raw owning pointers и не выпускают исключения.
- `ImageView` non-owning; допустимы только `Gray8`, `RGB8`, `RGBA8` в RGB/RGBA order. Размеры, stride и произведения проверяются от переполнения.
- Первый failure обязательной стадии немедленно завершает анализ с тем же `ErrorCode`; fallback и частичный успешный результат запрещены. Известная предметная причина не заменяется `InternalError`.
- Успех содержит все M1–M5, пять relative asymmetries, `k`, score и quality. Низкая post-structural confidence даёт `quality.acceptable == false`, а не failure.
- `resultSchemaVersion = "1.0"`, `libraryVersion`, `algorithmVersion`, `methodologyVersion`, `modelVersion = null`; C ABI JSON также содержит `cAbiVersion = 1`.
- Все config/result JSON object keys — `camelCase`; enums сериализуются contract names; optional absence — JSON `null`; NaN/Infinity дают `SerializationFailed`; порядок вывода фиксирован.
- Все стадии чисты относительно файлов, логов и global mutable state. Единственный документированный global side effect: первый `Analyzer` через `std::call_once` отключает OpenCL и ставит OpenCV threads в 1.
- Не использовать randomness, порядок `unordered_*`, timestamps или absolute paths в result JSON.
- `leaf-core` и `leaf-core-c` не читают файлы и не зависят от `imgcodecs`; JPEG/PNG, BGR→RGB, atomic output и debug directories принадлежат CLI.
- Debug — нестабильный desktop-only target `leaf-core-debug`, только при `LEAF_ENABLE_DEBUG=ON`; он не входит в C ABI, result JSON и вычисления.
- M1–M4 публикуются normalized; M5 — degrees `0..180`; `Ai=(Li-Ri)/(Li+Ri)`, `k=sum(Ai)/5`, score использует `abs(k)`.
- Golden tolerances только для synthetic/labeled fixtures: keypoint `≤ 5 px`, length `≤ 5%`, angle `≤ 3°`, asymmetry `≤ 0.005`. Неразмеченные `testdata/` — только smoke/negative.
- Не добавлять в implementation commits исходные `docs/leaf-core-spec.md`, утверждённый design, `testdata/` или посторонние untracked files.
- Каждая задача проходит два независимых review gate: (1) соответствие spec/design; (2) качество границ, владения, determinism, ошибок и тестируемости.

Outcome<ImageView> validateImage(ImageView v) noexcept {
  const std::int64_t bpp=v.format==PixelFormat::Gray8?1:v.format==PixelFormat::RGB8?3:
    v.format==PixelFormat::RGBA8?4:0;
  if (!bpp) return Outcome<ImageView>::failure({ErrorCode::UnsupportedPixelFormat,Stage::Input,"pixel format"});
  if (!v.data||v.width<=0||v.height<=0) return Outcome<ImageView>::failure({ErrorCode::InvalidImage,Stage::Input,"dimensions/data"});
  if (std::int64_t(v.width)>INT32_MAX/bpp || v.stride<std::int64_t(v.width)*bpp ||
      std::uint64_t(v.stride)>SIZE_MAX/std::uint64_t(v.height))
    return Outcome<ImageView>::failure({ErrorCode::InvalidImage,Stage::Input,"stride/overflow"});
  return Outcome<ImageView>::success(v);
}

- [ ] **Step 3: Implement minimal complete geometry.** Use cumulative Euclidean arc lengths and segment interpolation; build `yAxis=normalize(apex-base)`, `xAxis={yAxis.y,-yAxis.x}`, `scale=arcLength(path)`. Regression computes centered least-squares principal direction and orients it by endpoint progression. Ray intersections use determinant with epsilon `1e-12*scale`; deduplicate vertex hits. `sameSideContourArc` walks both closed-contour directions, rejects any interior sample whose normalized X changes sign or whose arc crosses base/apex separator, and fails on equal valid arcs within supplied tolerance.
